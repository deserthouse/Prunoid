## 一、总体结论

**数据与状态机是三项目中最扎实的，但两处接线事故让核心可用性受损，零 crash**：静态审计确认状态纪律标杆（单一 UiState + update{} 原子更新 + busyOp + msgSeq）、过滤全键 remember、量化确认句等；AVD 走查确认 SDK library/Stats 可视化精致、On-open 补扫正常、深色/i18n/合规完整。但走查抓到 **P1：无 root 环境 "Apply selected (N)" 零反馈死按钮**（叠加 Working mode 虚报 "Full capability"）；静态抓到 **P-1：订阅源 URL 可见不可点（真热区是不可见单空格）** 与 **P-2：清除全部 IFW 无确认**。合计静态 12 项 + 走查 6 项——问题数最多，但大多是"最后一步接线"，骨架不需动。

## 三、修复路线图（建议施工顺序与量级）

1. **先修 B-1（P1，半天内）**：禁用态视觉可辨 + 按钮下原因行 + Working mode 如实反映能力（探不到 root 自动落 Audit only）——三层一次做完，别只改视觉。
2. **接线与确认批量（一天量级）**：P-1 clickable 移到可见 URL 行（删 `Text(" ")`）；P-2/P-3/P-4/P-5 四个确认弹窗（复用现成量化确认句模式）；**注意走查已证实**：确认交互本身设计是好的，缺的只是这四处接入。
3. **B-2 空态下拉（半天）**：下拉宿主包住空态视图 + 扫描指示器；顺手 B-5 空态补指引；修完 grep 全工程同类"空态分支替换宿主"结构（静态篇 P-7 同源模式）。
4. **视觉/性能小批**：B-3 行距、P-6 runBlocking→suspend+LaunchedEffect、P-7 声明开关接 `_state`。
5. **P3 顺路**：B-4 snackbar 去重、P-8 警示横幅统一（复用列表页组件）、P-9 触控 48dp、P-11/P-12。
6. 修完后跑 AVD 篇"验证通过项"回归基线（重点：On-open 补扫、SDK/组件双视图、Stats 环图恒和 100%）+ root 实例正向路径复验（Apply 确认框）。

## 四、本项目是样板的部分（别的项目要抄这里的，别丢）

- **状态纪律**：单一 AppUiState + `update{}`、`withBusy` 操作级忙碌 + finally 保底、msgSeq 同文本 Snackbar 连弹、现场口径（liveDisabled）与记账口径（applied）分离；
- **安全交互文案**：量化确认句（N 个 SDK / M 个组件 + 分类明细 + RISKY 排除计数 + 引擎行）、框架应用硬拦截 vs 普通系统应用警示分层、SafetyBadge 图标+文字+后果 CD；
- 过滤/排序/聚合全键 remember（性能样板）、图标后台预载注释、搜索命中原因提示、环形图最大余数法、Snackbar 被 sheet 遮挡→内嵌状态行的实机实证修正；
- 唯一全量 MaterialExpressiveTheme + MotionScheme。

## 五、跨项目共性中与本项目相关的

- **静默无反馈路径**（三项目共性病灶）：本项目的份额就是 B-1/B-2（也是最重的份额）；
- **破坏性操作确认不一致**（静态篇共性第一）：P-2/P-3/P-4/P-5 是主要欠账方；
- **共享组件模板**（战略 #10）：与 OptIcon 的两份互认复制（SettingsCard/SettingRow/版本徽章等）在第三个同类项目动工前抽模板；
- **状态真实性**（走查共性第二）：B-1/B-6 的 Working mode 虚报是典型；
- 未覆盖项：TalkBack/大字体矩阵审查（双篇均未做，排期时补）。
