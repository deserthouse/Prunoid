## 一、审计结论

工具链基线完全合规；**状态管理与安全交互设计是三项目中最严谨的**（单一 UiState + `update{}` 全程原子、操作级 busyOp + finally 保底、量化确认句、框架硬拦截/系统警示分层、现场口径与记账口径分离、全键 remember、安全色"色不单独表意"契约）。MaterialExpressiveTheme + MotionScheme 也是三家唯一的全量 M3E 落地。

主要短板集中在两类：**①两个高危 UX 缺陷（URL 不可点、清除全部 IFW 无确认）；②破坏性操作确认不齐**（批量禁用/全局禁用/删源均无确认）；另有 runBlocking 主线程阻塞与声明开关疑似不回显两处功能性隐患。

## 三、修改意见（按优先级）

### 立即修（高收益/低成本）

1. **P-1 URL 不可点**：把 `SettingsSections.kt:487-496` 的 clickable 移到 `:462-479` 的可见 URL 行上（参考同文件 CreditEntry :81-104 的"整行触达"写法），删除不可见 `Text(" ")`。
2. **P-2 清 IFW 确认**：`清除全部` 按钮包一层 AlertDialog，正文引用现有 `recovery_ifw_count` 数量 + `recovery_clear_desc` 后果说明，确认键 error 色（本文件恢复备份对话框 :224-244 是现成模式）。
3. **P-3/P-4/P-5 确认补齐**：批量禁用未识别组件、删除自定义源、全局禁用 SDK 各加确认；未识别组件与全局禁用可复用详情页量化确认句模式（DetailScreen:484-508）显示"N 组 / M 组件 / 影响 K 应用"。
4. **P-6 runBlocking**：`listBackups()` 改 suspend（`engine.listBackups()` 本身已在 IO 上跑，去掉 runBlocking 壳），SettingsScreen 侧改 `LaunchedEffect { backups = vm.listBackups() }` 或 VM 状态承载。

### 近期修（需小批量改动/先验证）

5. **P-7 声明开关回显**：`DeclarationsStore` 状态接入 `_state`（声明集 Set<String> + enabled 入 AppUiState），`toggleDeclaration` 完成后 `_state.update`；ArchiveSheet 的 `declOn` 改读 state。修复前先按"需运行验证"清单真机确认现象。
6. **P-8 root 警示条统一**：详情页底部栏复用列表页的 Surface 横幅（WarnContainer/Dark 正确配对），抽成共享小组件放 Components.kt。
7. **P-9 触控目标**：订阅源行 IconButton 恢复 48dp 默认（去 `Modifier.size(40.dp)`），busy 占位 Box 同步 48dp。
8. **P-11 反馈与链接**：sourceLink 行改可点（CreditEntry 模式）或加长按复制；备份份数保存给真实成功文案（新增 string），按钮文案从"添加"改"保存"。

### 顺手清理

9. **P-10 scrollingUp**：与 OptIcon 联合收敛（见共性建议），短期可先把全局 Map 改为 `rememberLazyListState` 的 remember 封装。
10. 未使用的 navigation-compose 依赖：移除或注释保留理由。

## 六、跨项目协同事项（引自横评）

- 设置族组件（SettingsCard/SettingRow/SectionTitle/CreditEntry/SearchField/版本徽章/彩蛋）与本仓注释多处标注的"OptIcon 样板"已是两份互认复制——**第三个同类项目动工前抽共享模板**；scrollingUp 两套实现联合收敛为 rememberLazyListState 派生扩展。
